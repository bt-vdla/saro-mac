## 10. Solution overview

Saro for Mac is one native macOS 27 app with no server and no third-party code. SwiftUI sits on a local SQLite ledger, and the AI is Apple Intelligence on the Mac. The alpha needs no account and no network; BYOK runs only in Saro Lab, a separate founder build.

<?claude block dia?>

Every AI call goes from the SaroAI actor through the SafetyGate to a model tier, and the default tier is Apple on-device, so nothing leaves the Mac. Only two dashed opt-in routes cross the Mac boundary: Apple PCC, which needs an entitlement and is not in the alpha, and BYOK, which reaches the Anthropic API from the Saro Lab build only.

| Layer | Choice | Why | Rejected alternative |
|---|---|---|---|
| Minimum OS and hardware | macOS 27.0+, arm64. Testers need an M1 or later with Apple Intelligence on and an English device language. | Live and file speech providers, the runtime `contextSize` (8192 measured on the M5), the model `variant` and image attachments exist only on 27. | macOS 26: 4096 context, no still captions, no variant. Intel: `deviceNotEligible`. |
| Codebase layout | One Xcode 27.1 project in `apple/` of the saro repo, branch `mac/foundation` from `ad4c7ed`. One multiplatform app target; local package SaroKit with no AppKit; Swift 6.4 strict concurrency; `@Observable` stores. | The TS and Python sources next door stay the spec, and evals read `backend/evals/cases` in place. Keeping AppKit out of SaroKit reuses about 70% of code on iPhone (estimate). | A separate repo; five packages; a separate Dev bundle id that strands the dogfood journal. |
| App shell | One `Window`: a `NavigationSplitView` (days, What Saro knows, Trash), the Day in the detail pane, an inspector for What Saro noticed. Settings scene, `MenuBarExtra`, one `CommandRegistry`. No account; optional Touch ID lock. | Keyboard, undo, focus and VoiceOver come mostly free. A local-first app needs no sign-in. | `WindowGroup`, where two windows fight over the recorder; the React UI in a WebView. |
| Day surface | An ordered day board: entry cards in time order in a `LazyVStack`. Each card opens to an AVKit player and a tap-to-seek transcript. Cards are pure SwiftUI, reusable by the later canvas. | The canvas is about 14k TS lines and 9-11 dev-weeks to parity, and it is not the moat. | The free-form `NSScrollView` canvas in the alpha (+6-7 dev-weeks). |
| Persistence | System SQLite 3.54.0 with FTS5 behind a 400-line in-house wrapper: one writer actor, WAL, `foreign_keys=ON`, `secure_delete=ON`. Append-only rules are triggers. Media are files under `Media/<local_day>/`. | The self-model needs append-only enforcement, unique keys, `GROUP BY local_day` aggregates and FTS5 in one file. No dependency. | GRDB 7: a dependency for about 2 days saved, kept as the approved fallback. SwiftData with CloudKit: no unique constraints, last-writer-wins. |
| Sync and backup | Local-only alpha. Daily `VACUUM INTO` snapshots (keep 7), plus Export to `.saroexport` and Import (idempotent by UUID) from the first dogfood build. Sync-ready schema; `CKSyncEngine` in P6. | An export with no importer is not a backup. Video is 19-23 MB per minute, and a one-Mac alpha does not need sync. | CloudKit before the alpha (+5 weeks); SwiftData CloudKit mirroring. |
| Capture | One `@MainActor` `CaptureController` over an `AVCaptureSession`. Movie files fragment every 2 s; rows are written before the first frame; a launch sweep reconciles rows and files. No length cap. | A fragmented file survives `kill -9`, so "never lose a recording" is structural. | The web's in-memory blobs, 30 s retry and 5-minute caps; two capture owners. |
| Speech | Live path (`SpeechTranscriber` via `CaptureInputSequenceProvider`) for captions and checkpoint text only. File path (`AssetInputSequenceProvider`) re-transcribes each finished file as the transcript of record, with word times and confidence. | Live samples keep arriving while the movie output is paused and run on the session clock. The file pass keeps quotes verbatim and seek times exact. | Live results as the stored transcript; gpt-transcribe; `providerWithSession(from:)`, which creates a second session. |
| AI tiers | Apple on-device by default, and the only AI in the TestFlight alpha. PCC after the alpha if Apple grants it. BYOK (Claude first) in Saro Lab. The heuristic twin always. Detail in section 11. | Free, offline and private by default. BYOK lets the founder bench a frontier model without changing the default. | MLX or plug-in models in the alpha; PCC in the alpha, blocked by error 1046. |
| Safety gate | One `SafetyGate` actor in SaroKit on every path: transcript quality, phrase gate, on-device classifier, output gate. It runs on the Mac before any model call, BYOK included. | No moderation model exists on the device. The graded classifier scored 11 of 13 at about 170 ms and caught all 4 real risks. | Guardrail errors as risk signals; a second, weaker gate for the no-AI path. |
| Search | Alpha: a substring filter (`localizedStandardContains`). P8: FTS5 with `bm25` and the web field weights in a Cmd-K palette. | Weeks of entries filter instantly. FTS5 later replaces about 500 lines of custom ranking. | Porting the 1,264-line search engine now; Core Spotlight, which puts journal text in system search. |
| Capture from anywhere | `MenuBarExtra`; a Carbon `RegisterEventHotKey` hotkey (default Ctrl-Cmd-J) that opens a non-activating `NSPanel` voice pill; paste and drop on the pill and the board. | This tests the Mac premise. Carbon needs no Accessibility permission and no dependency. | The KeyboardShortcuts package; `NSEvent` global monitors. |
| Distribution | TestFlight for Mac under the company account: Bharat and the developer internal, testers external. The first external build goes to Beta App Review on Mon 15 Mar 2027, 18 days before Alpha-0. Mac App Store 1.0 at parity. Saro Lab is a Developer ID build for the founder's Mac only. | Guideline 5.1.1(ix) wants a legal entity for sensitive data. TestFlight handles updates and crash reports. Lab keeps the network entitlement out of every tester build. | Developer ID builds for testers; App Store Connect roles for testers; BYOK in the TestFlight alpha. |
| Privacy posture | App Sandbox with camera, audio-input and user-selected-file entitlements. The TestFlight build has no `com.apple.security.network.client`, asserted in CI. Writing Tools off in editors; a content-free "What Saro read" log. Saro Lab adds `network.client`. | The sandbox enforces "Saro has no way online". Lab is the only build where that line is false, and testers never get it. | Treating a missing `network.client` as proof by itself; screen-share hiding before testing. |
| Dependencies | None from third parties: Apple frameworks and system SQLite. Fonts are Newsreader, Geist and Geist Mono under the SIL OFL. BYOK calls the Anthropic HTTP API through Saro's own executor on `URLSession` (D-22). | The stated preference, and nothing needs more. | GRDB, KeyboardShortcuts, Sparkle, Sentry; Anthropic's ClaudeForFoundationModels package (beta), kept as the D-22 alternative. |

Whether the public app carries BYOK is decision D-19, due at the iPhone-or-canvas call on Fri 21 May 2027. Until then "Saro has no way online" stays true for every build testers receive.

Open question: should Saro Lab open the founder's dogfood journal (same bundle id) or keep its own container (recommended)?

### What is retired

The FastAPI backend, Supabase, every OpenAI call, sign-in and accounts, and the web upload machinery are retired. The web app freezes at `ad4c7ed` as an offline demo and test oracle. `prompts.py`, `safety.py`, `schemas.py`, `evals/checks.py` and the 25 eval cases stay in git as specs; the full list is in the Retired components appendix.
